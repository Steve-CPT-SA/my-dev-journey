# My Full-Stack, Python & AI Project Ladder

My roadmap for progressing from JavaScript fundamentals to full-stack development, Python, and AI, building toward practical **Decision & Opportunity Systems**.

My goal is to build projects that demonstrate technical growth, independent problem-solving, and the ability to turn programming concepts into useful software.

## Core Philosophy

**Standard Project + My Twist + One Major New Concept = Portfolio Project**

I want to build familiar types of projects with my own practical angle, rather than following tutorials without understanding the underlying concepts.

## Rules

- Alternate JavaScript and Python early.
- Introduce databases before React.
- Introduce AI before the capstone.
- Separate major concepts into their own projects.
- Use sample or demo data in public repositories.
- Build a reusable Decision Support Platform rather than a personal relocation tracker.

## Flagship Project Path

The Decision Support System starts as a simple JavaScript tool and evolves into an AI-powered decision platform:

1. **Project 12:** Decision Support System, the core scoring and comparison logic.
2. **Project 17:** rebuilt in React and TypeScript.
3. **Project 18:** connected to a FastAPI backend and PostgreSQL database.
4. **Project 19:** migrated to Next.js.
5. **Project 20:** user accounts and authentication added.
6. **Project 21:** AI-assisted summaries, scoring suggestions and option comparisons.

Users will compare options such as job offers, business opportunities, courses, projects, investments and countries. Each option is described by cost, effort, risk, reward and requirements.

## Development Principles

- **Build incrementally:** start with a working minimum version, then add features.
- **Write maintainable code:** clear naming, modular functions, separation of concerns.
- **Validate input:** handle invalid data and expected errors.
- **Test important behaviour:** add testing as projects become more complex.
- **Protect secrets:** never commit API keys, passwords, tokens or other credentials.
- **Use sample data:** use fictional or public data in public repositories.
- **Document projects:** purpose, features, technologies, setup and lessons learned.
- **Understand before advancing:** prioritise understanding over speed.

This roadmap is a guide, not a rigid contract. Scope, technologies and priorities may change as I learn.
